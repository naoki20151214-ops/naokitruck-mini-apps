扉は閉まっているのに、装置が「開いている」と表示して動かない。

そんなとき、扉そのものが故障したとは限りません。

装置は現物を直接理解するのではなく、センサーの信号を条件と照らして動作の可否を決めます。

この記事の主役は、半導体製造装置のセンサーとインターロックです。センサーは圧力や位置などの状態を信号に変える入口。インターロックは、決められた条件が成立しないときに動作を許可しない、または運転を停止側へ移す仕組みとして捉えます。「危ない」の中身には人に関わる危険と、装置や工程にとって不適切な状態があります。両者の目的を混ぜず、実物から制御判断までの経路をたどります。[S03][S04][S09]

この記事でわかること

  • なぜ装置は圧力・流量・温度・位置・扉などを確かめるのか
  • Sensor → Signal → I/O → Controller → Logicから、許可・禁止・停止へ至る流れ
  • インターロック発生後、実設備と信号経路のどこから原因を絞るか
  1. なぜ検知と停止の仕組みが必要か
  2. 装置が状態を判断する経路
  3. 人・装置・ウェハ・工程をどう守るか
  4. 停止後に何を順に見るか
  5. 六つの原因候補をどう分けるか
  6. 設備保全の仕事とのつながり

1. なぜ、装置は動く前と動いている間に状態を確かめるのか

必要な理由は、装置の画面上の命令だけでは、現実の圧力や扉の位置がわからないからです。半導体装置には、処理室の真空、ガス流量、温度、バルブや搬送機構の位置、ウェハやキャリアの有無を測る部品が使われます。ただし、監視項目とセンサーの配置は装置ごとに異なります。これらを一つの装置の標準構成として列挙しているのではなく、安全の枠組みと各社の製品例を組み合わせた説明です。[S08][S11][S13][S14]

たとえばロードロックや処理室の圧力を測る真空計、流量を測って調整するMFC、ウェハキャリアの有無を検出する光学センサーには、それぞれメーカーの実装例があります。装置が必要な状態を確かめずに次の動作へ進めば、圧力・流量・位置などの条件がそろっていないまま操作が進む可能性があります。どの条件で何を禁止するかは個別の設計によります。[S14][S11][S13][S04]

逆に、条件が満たされないときに開始を許可しない仕組みがあれば、不適切な順序や状態で動作することを抑えられます。運転中に条件が外れた場合は、設計された停止側へ移すこともあります。インターロックの役割は「何でも即座に全部止める」ことではありません。対象の危険や工程、装置に応じて、何を許可し、何を禁止するかが定められます。[S04][S09]

2. センサーから停止判断まで、どこを信号が通るのか

装置は「危険」を人のように理解しません。物理状態をセンサーが電気信号やデジタル情報に変え、I/Oという制御装置の入出力を通して、コントローラーが受け取ります。そこで設定された条件と比較し、動作許可（Permit）か禁止（Inhibit）かを決め、必要な出力を駆動部へ送ります。次の一本の線は、IEEEのセンサー定義、産業用コントローラーのI/O資料、インターロックの説明をつないだ記事上の整理です。すべての半導体装置の配線図を表すものではありません。[S03][S06][S04]

Physical state → Sensor → Signal → I/O → Controller → Logic → Permit / Inhibit → Output → Actuator

Sensorは実際の状態を検出する部品、Signalはその結果を伝える情報です。I/Oは信号を制御装置へ入れたり、制御装置から出したりする接点。Controllerは入力値を受ける制御装置、Logicは「この条件なら動作可」といった判定です。Actuatorはバルブやモーターなど、命令を受けて働く側を指します。産業用機器にはON/OFF入力のほか、0/4–20 mAや0–10 Vのような連続量の入力例がありますが、通信方式や電気的仕様は機種によります。[S06][S11]

圧力計の一例では、圧力に応じた0–10 Vの出力がコントローラー側へ渡ります。そこで信号の範囲を測定値へ対応付け、装置が定める条件と比べる、という考え方です。ただし、0–10 Vという値はMKSの製品例であり、どの真空計も同じ出力という意味ではありません。しきい値も装置固有です。画面に出る圧力が実物と違うときは、現実の圧力、センサー出力、I/Oでの値、画面表示を同じものとして扱わず、一段ずつ比べます。[S02][S06]

ON/OFFの例が扉や位置の検出です。扉が物理的に閉じていても、スイッチが作動していない、配線が途切れている、I/Oに信号が届かない、といった場合には制御側が「閉じた」と認識できません。逆に画面が正常を示しても、センサーの測定点や応答には限界があります。表示だけを現物の証明にしないことが重要です。[S10][S06][S01]

3. インターロックは、何を守るために働くのか

「止まった」という見た目が同じでも、守る対象は同じではありません。人に関わる安全機能と、装置の損傷を防ぐ条件、ウェハ・工程にとって不適切な順序を防ぐ条件を分けて考えます。この三つは理解のための分類であり、装置メーカーの正式なアラーム分類を示すものではありません。[S08][S09][S04]

人に関わる例は扉やガードです。安全インターロックスイッチには製品例があります。ただし、スイッチを付けただけで装置全体がSEMI S2に適合するわけではありません。SEMI S2は半導体製造装置のEHSに関するガイドラインで、安全機能の設計は個別の危険とリスク評価に依存します。安全PLC、二重化、手動リセットをすべての装置で一律に要求するという説明はしません。[S10][S16][S08][S09]

装置を守る例としては、ポンプ、ヒーター、モーターなどを不適切な運転条件から守る考え方があります。工程側では、圧力、ガス流量、バルブ位置、ウェハの有無などが開始許可や順序の条件になり得ます。条件が外れたまま処理を続ければ、狙った工程条件が成立しない可能性があります。ここでいう「ウェハを守る」は、あらゆるウェハ不良を防ぐという意味ではなく、不適切な状態・順序で搬送や処理を進めないという役割です。実際に何を止めるか、どこで止めるかは装置ごとに確認します。[S04][S02][S11][S13]

また、画面に「Alarm」と出たら必ず停止、「Interlock」と出たら必ず同じ停止動作、と名前だけで決めることもできません。通知なのか、開始を許可しないのか、運転中の出力を止めたのか。保全では名称より、実際に作用した出力と禁止条件を確認します。[S04][S11]

4. インターロックが出たら、何を順番に見るのか

最初にするのは、部品を交換することではなく、どの条件が、いつ、どの動作を止めたかを特定することです。以下はResearchの複数資料を組み合わせた診断の順序です。実機の作業手順や安全措置を置き換えるものではなく、現物確認や測定は装置メーカーの手順に従います。[S01][S06][S07]

  1. 発生履歴を見る。最初のイベント、発生時刻、関連する警報、直前の操作を並べる。後から出た警報を最初の原因と決めない。
  2. 外れた許可条件を探す。圧力、流量、温度、位置、扉など、どの値・状態がNGになったかを特定する。
  3. 表示と推移を比べる。現在値だけでなく、変化の順序、設定値、関連する測定値との整合を見る。
  4. 現物の状態を確かめる。許された安全な方法で、表示された異常が実際にもあるかを確認する。独立した測定や目視が可能かも装置手順で判断する。
  5. 信号経路を追う。センサー出力、電源、配線・コネクター、I/O入力、制御側の認識を順に比べる。
  6. 判断と動作を分ける。しきい値・設定・論理条件を確認した後、命令が出たか、駆動部や機械が実際に動いたかを見る。

この順序なら、画面の表示と実物が同じ方向に異常なのか、途中のどこかで食い違ったのかが見えます。たとえば圧力が本当に高いなら、真空計の交換だけでは解決しません。一方、独立した確認では圧力が正常なのに制御側だけNGなら、センサーからI/Oまでを詳しく調べます。これは資料をつないだ診断上の整理であり、単一メーカーが定めた共通手順ではありません。[S01][S02][S06][S14]

信号の入口だけをさらに確かめたい方は、この記事のセンサーから制御判断までの流れを、停止履歴と照らして読み直してください。次の節では、同じ警報から六つの原因候補を分けます。

5. 原因候補は、六つの層に分ける

インターロックが出た場所は、根本原因の住所ではありません。「扉が開いている」「圧力が足りない」と画面に出ても、その条件を成立させる現物と信号の間には複数の層があります。次の分け方はResearchの故障診断、I/O資料、装置部品の例を組み合わせた記事上の整理です。[S01][S06][S04]

表示と現物を突き合わせるための六つの原因候補
層 確認する食い違い 例
実設備異常 現物も条件を満たしていないか 圧力、流量、温度などが実際に許可条件の外にある
Sensor異常 現物とセンサー出力が一致するか ずれ、汚れ、校正の問題、検出位置のずれ
Wiring異常 出力が接続先まで届いているか 断線、ゆるいコネクター、電源やノイズの問題
I/O異常 入力チャネルが信号を正しく読んでいるか 入力種別、スケーリング、チャネルの食い違い
Logic異常 制御側の条件と現在値の関係が妥当か しきい値や設定、動作許可条件の不一致
Mechanical position異常 命令に対して機械が所定位置へ到達したか バルブや機構が途中で止まる、位置が成立しない

実設備異常を先に除外せず「誤検知」と決めるのは危険です。反対に、実物が正常に見えても、センサー出力が正しいとはまだ言えません。センサーの断線・短絡、校正ずれ、一時的なノイズといった可能性を、制御側の表示と現物の比較から絞ります。[S01][S07]

位置については特に、「機械がその位置にある」と「コントローラーがその位置と認識する」を分けます。近接センサーには非接触で位置を検出する製品例があります。実際に到達していないなら駆動や機械側、到達しているのに検出が変わらないならセンサーや取付け側、センサー出力は変わるのに制御入力が変わらないなら配線・I/O側へ進みます。[S12][S06][S01]

扉の例でも同じです。扉を閉めたという観察、スイッチが検出したという事実、I/OがONを受けたという事実、Logicが許可したという結果は、別々に確認します。安全機能を安易にバイパスして動作だけを確かめるのではなく、指定手順で原因を特定します。安全機能の設計や試験条件は個別装置に依存します。[S10][S16][S08]

6. 圧力と流量の警報では、測定器の外側も見る

圧力インターロックなら、まず本当に必要な圧力に達していないかを確かめます。現物側にはポンプ、バルブ、気体の流入、漏れなどの候補があり、信号側には真空計、配線、I/O、しきい値があります。INFICONは処理室・搬送室・ロードロック向け真空計の製品例を示し、MKSは圧力に応じた電圧出力を持つ計器の例を示しています。そこから先の原因分岐は、資料をつないだ整理です。特定の圧力値を全装置の停止基準にはできません。[S14][S02][S01]

流量の警報なら、MFCの設定値と実測値だけでなく、供給側、バルブ、流路、フィードバック、通信や配線を分けます。MFCは流量を測って制御する機器で、アナログ信号やデジタル通信を備えた製品例があります。Flow switchは設定した流量条件をスイッチ信号に変える別の構成例です。「流量が不足した」という結果からMFC本体の故障を直ちに決めることはできません。[S11][S05][S01]

温度も同じで、表示値だけを原因としません。熱電対やRTDには異なる測定原理があり、センサーの種類、取付け位置、加熱・冷却側、I/O、しきい値を分けます。処理温度の管理と装置の過熱保護は目的が異なるため、同じ「温度警報」という名前から一つの仕組みを想像しないことが大切です。[S15][S06]

7. この切り分けが、設備保全の仕事になる

設備保全では、「止まった部品を交換する」より前に、どの状態が崩れたかを証拠で確かめます。イベント履歴、値の推移、現物の状態、電気図面、I/O一覧、制御条件を重ねれば、実設備、センサー、配線、I/O、論理、駆動機構を混同しにくくなります。この順序はResearch資料を組み合わせた実務上の整理で、メーカー固有の保全手順を置き換えるものではありません。[S01][S06][S07]

予防保全では、センサーの点検・清掃・接続確認・校正や、指定された機能確認が候補になります。安全スイッチの確認はメーカー文書と装置側の安全手順に沿って行います。機械位置のずれと電気信号の異常、真空系の実際の異常と真空計の異常を分けて考えられることが、停止からの復旧だけでなく再発を防ぐ手がかりになります。[S07][S16][S01]

工場でセンサー、配線、PLC、空圧、モーターの経験がある人は、この信号経路の読み方を半導体装置にもつなげられます。一方、真空、ガス、ウェハ搬送、装置固有の安全条件は別途理解が必要です。これは仕事に必要な技術の接続であり、個別求人の条件を推測したものではありません。[S06][S08][S11][S14]

よくある疑問

扉が閉まっているのに「Door Open」なら、スイッチ交換ですか？

まだ決められません。扉とスイッチの位置、スイッチ出力、配線、I/Oでの認識を分けて確認します。物理的に閉じていても、制御側が閉状態を受け取っているとは限りません。[S10][S06]

Alarmが出たら必ずインターロックで停止しますか？

名称だけでは判断できません。通知、開始禁止、運転中の停止など、装置が実際に行った動作を確認します。[S04][S11]

センサーの値が正常なら、装置も安全ですか？

それだけでは証明できません。測る場所、応答、配線や入力側の状態には限界があり、必要に応じて現物を安全な手段で独立に確かめます。安全機能の妥当性も、個別の設計とリスク評価で判断します。[S01][S08]

3行でまとめる

装置はセンサーから届いた状態を、I/Oと制御条件を通して動作の許可・禁止に変えます。
人の安全、装置の保護、ウェハ・工程の条件は目的を分けて考えます。
停止後は警報名だけで部品を決めず、現物から信号、I/O、Logic、機械動作へたどります。
