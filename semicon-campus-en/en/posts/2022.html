On October 13, 2026, Marvell, Microsoft, and Oracle announced that they have formed a new working group in the Open Compute Project (OCP) Security Track to standardize integrated HSMs for data centers. This announcement is not the launch of a finished product or the start of mass production. It is the stage where several companies begin drafting a common specification for hardware security built into servers. Marvell announcement

In AI services, the data that must be protected becomes huge, including training data, inference data, customer information, and the models themselves. This makes key management important: where encryption keys are generated, where they are stored, and who can use them. This move aims to build a key-protection mechanism into the servers that run AI as standard components and protocols.

What was announced

The three companies listed areas the specification will cover, including secure key caching inside the server, encryption key lifecycle management, hardware boundaries, key vaults, and attestation chains. A key cache is a mechanism that temporarily holds keys used frequently in encryption. However, if keys are simply placed in ordinary memory, they risk being read by the OS or malicious programs. With an integrated HSM, the goal is to handle keys inside a protected area. Scope of the announced specification

The three companies said they plan to draft an open specification targeting NIST FIPS 140-3 Level 3, releasing an initial draft around the 2026 OCP Global Summit and version 1.0 after that. This is a plan presented by the companies. It does not mean that specification 1.0 is complete, that products are in mass production, or that certification has been obtained.

On the same day, Microsoft also described Project Tessera, which builds on Azure Integrated HSM. It is an effort to open-source the architecture, specifications, protocols, drivers, software, firmware, and a reproducible build environment. According to Microsoft, it demonstrated HSM partition replication and a resiliency ring between the Tessera Integrated HSM and the Marvell LiquidSecurity 2 HSM, using post-quantum cryptography for HSM-to-HSM communication. This is a report on a demonstration and does not indicate that a final OCP standard has been approved. Microsoft's description of Project Tessera

What is an HSM?

HSM stands for Hardware Security Module. It is a device or function that separates encryption keys from the general-purpose OS and ordinary memory, and performs cryptographic operations inside a protected boundary. For example, instead of leaving the key that encrypts cloud data in an application's memory, the key is stored inside the HSM. The application asks, "Please encrypt this data," but the system can be designed so the key itself can never be taken out.

Traditionally, a common setup placed the compute server and a network-connected HSM as separate devices. In this setup, every key operation requires network communication, and there is also a dependency on the HSM as a centralized service. Microsoft describes Azure Integrated HSM as a design that sits close to or inside the server, keeping keys within the HSM boundary while avoiding the network round trips of a centralized remote HSM. Microsoft's description of Azure infrastructure

What FIPS 140-3 Level 3 means

FIPS 140-3 is a NIST requirements standard for evaluating the design, implementation, and operation of cryptographic modules. It has four security levels, and the evaluation covers the module specification, interfaces, user roles and authentication, software and firmware, physical security, management of sensitive security parameters, self-tests, lifecycle assurance, and more. NIST FIPS 140-3

In other words, "Level 3" does not just describe a particular encryption algorithm or a chip's processing speed. It is a set of requirements covering the whole cryptographic module: how keys are stored, who can operate it, how tampering is detected, and how security is maintained during failures and updates. The three companies are targeting Level 3, but as of the announcement it has not been confirmed that future integrated HSMs are certified.

What this means for the semiconductor industry and AI services

What makes this important is that it goes beyond each cloud provider's own custom implementation and tries to create common ways to connect servers, security chips, CPUs and SoCs, firmware, and management software. If the specification is widely adopted, it may become easier to link key protection and workload attestation even across HSMs and servers from different vendors.

In confidential computing for AI, you need to confirm that the workloads processing input data and models are "really running in an attested environment." Workload attestation here means checking the state of the programs and servers being run, and letting only approved processes use the keys. By combining HSMs, measured boot, attestation, Confidential Computing, and more, you can build a chain of trust from hardware to software. However, real-world security also depends on each implementation, its settings, and how it is operated.

Post-quantum cryptography is another point to watch. It is encryption technology for moving to new methods, given the risk that future quantum computers could break today's public-key cryptography. Microsoft said it used post-quantum cryptography for HSM-to-HSM communication in this demonstration, but it has not been decided which algorithms the final specification will require, how certification will work, or when it will be built into products.

Remaining challenges and what to check next

First, we need to check the progress of standardization. Even if an initial draft is released, that does not necessarily mean the participating companies, the mandatory items in the specification, interoperability testing, or final OCP approval are settled. The next focus is when version 1.0 will be released and which products will comply.

Second, FIPS 140-3 certification status must be checked product by product. NIST's Implementation Guidance has been updated for sub-chip cryptographic subsystems, processor cryptographic accelerators, key encapsulation mechanisms, and more. FIPS compliance cannot be judged from a product name alone. You need to check the module covered, the scope of evaluation, and the validation results. NIST Implementation Guidance updates

Third, real measurements of performance and operation. Integrated HSMs may reduce network round trips, but these materials do not show latency, throughput, power consumption, or failure recovery from independent benchmarks. Key backup, firmware updates, the trustworthiness of manufacturing and the supply chain, and unifying key policies across different HSMs are also important issues for real-world use.

This announcement points toward treating key protection as a standard component in servers for the AI era. However, at this point, what has been confirmed is the start of standardization, a technical demonstration, and future plans. Going forward, checking the release of the OCP specification, interoperability testing, independent certification results, and the arrival of mass-produced products, in that order, will be the way to tell an announcement apart from real-world use.
