Learning level Beginner

In Episode 29, we learned that CUDA is a software platform that makes it easier to use GPUs for general-purpose computing. This time, we look at Tensor Cores, which run matrix calculations efficiently inside that GPU. You can follow along without working through any equations.

Tensor Cores are dedicated compute units that efficiently run matrix multiply-accumulate operations inside supported NVIDIA GPUs. They are not the GPU itself, not an all-purpose circuit used only for AI, and not a simple replacement for CUDA Cores. They show their strength when libraries and frameworks route supported calculations and data types to the right path.

First, let's clear up three misunderstandings

It is not the GPU itselfIt is a type of compute unit built into supported GPUs.
It is not necessarily AI-onlyIt is used heavily in AI, but it can also be used for scientific computing and other work that uses matrix math.
It does not replace CUDA CoresGeneral processing and dedicated matrix processing are split between the units that are best at each.

What do Tensor Cores speed up?

Their core job is matrix multiply-accumulate: multiplying several numbers, adding them up, and adding the result to an existing value. NVIDIA's documentation describes it as multiplying matrices A and B and adding the result to matrix C to get matrix D. In machine learning training and inference, each layer of a neural network repeats this kind of calculation a huge number of times.

However, AI workloads are not made only of matrix multiplication. They also include other operations and data movement, such as data preparation, branching, memory access, and activation functions. Even if Tensor Cores are fast, the whole workload does not necessarily speed up by the same factor.

What Tensor Cores directly speed up is things like matrix multiply-accumulate in supported formats. They are not circuits that make an entire app faster unconditionally.

What is mixed precision? Balancing speed and accuracy

How finely a computer represents numbers is called precision. In general, lower-precision formats are easier to handle in large quantities at once and reduce memory use and data transfer. On the other hand, making everything low precision makes rounding errors and values falling outside the representable range more likely.

Mixed precision is the idea of using relatively light formats for inputs and bulk calculations, and wider formats for accumulated results and parts where accuracy matters. In early Tensor Cores, a typical example was multiplying FP16 inputs and accumulating in FP32. The formats available today depend on the GPU generation and software, and some products support FP16, BF16, TF32, INT8, and others. Later generations can also handle FP64.

Check data types for each generation

You cannot say that "with Tensor Cores, every data type runs at the same speed." Supported formats, compute performance, and input size requirements change with the GPU architecture and library version. When choosing products or estimating performance, check the official specs for the target GPU.

How do they share work with CUDA Cores?

ItemMain roleWhat beginners should know

CUDA CoreRuns more general numerical operations and various other processingStill needed even when Tensor Cores are present

GPU work includes parts that fit neatly into matrix multiply-accumulate and parts that do not. Tensor Cores and CUDA Cores are less like competitors and more like partners that split different jobs inside the GPU. It connects well if you think of it this way: on top of how CUDA opened GPUs to general-purpose computing, explained last time, supported matrix operations can now be sent down a dedicated path.

Does having the hardware make things faster automatically?

To use Tensor Cores, the calculation must be expressed in supported operations and data types, and the software must choose that path. Developers use them through libraries such as cuBLAS and cuDNN, deep learning frameworks, or APIs such as WMMA. Supported libraries can route suitable calculations to Tensor Cores.

Shape of the calculationLarge enough matrices and dimensions that split efficiently make it easier to keep the units busy.
Data supplyIf inputs cannot reach the units fast enough, waiting time increases.
Overall workload structureIf the parts that do not use Tensor Cores are long, the overall app speedup is smaller.

Why HBM and memory bandwidth come next

The more a compute unit can process at once, the more it needs a constant flow of input data and a way to receive results. In workloads with a lot of data movement relative to computation, Tensor Cores spend more time waiting, and memory can become the performance ceiling.

That is where HBM and memory bandwidth, which supply large amounts of data over a wide path close to the GPU, become important. Next time, from the viewpoint that "making compute units faster is not enough," we look at why HBM gets attention in GPUs for AI.

Frequently asked questions about Tensor Cores

Are Tensor Cores only for AI?

No. They are important because AI uses huge amounts of matrix math, but they can also be used for scientific computing and other work that uses supported matrix calculations.

If a GPU has Tensor Cores, are CUDA Cores unnecessary?

No. Tensor Cores handle supported matrix operations, while CUDA Cores and others handle much of the other processing.

Is mixed precision a way of making calculations inaccurate?

It is not simply lowering precision everywhere. It separates parts that can use light formats from parts that need higher precision, balancing speed and numerical stability. Validation for each use case is still needed.

With a Tensor Core GPU, does every AI get faster by the same amount?

No. The effect depends on supported data types, matrix size and shape, software, memory bandwidth, and the share of processing that does not use Tensor Cores.
