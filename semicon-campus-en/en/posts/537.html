Learning level Beginner

This article is for people who already know about CPUs and GPUs and want to move on to NPUs, which power on-device AI in smartphones and PCs.

An NPU (Neural Processing Unit) is a dedicated accelerator for running neural network inference on the device itself, with low latency and low power. It is not a failed substitute for a CPU or GPU. It gives up some versatility and tailors its circuits to the calculations AI repeats, working as a partner alongside them.

CPUDecisions, control, and a wide range of tasks
GPULarge-scale parallel computing
NPUMakes supported AI inference highly efficient

If you want to review the basics of CPUs and GPUs first, reading why GPUs are used for AI makes the division of roles easier to see.

What problem made NPUs necessary?

Naoki

We already have CPUs and GPUs. Why add an NPU too?

Professor Owl

Because devices started running AI inference over and over for the camera, voice, authentication, and more. On a device, power, heat, and waiting time became a heavy burden.

Naoki

So instead of calculating fast just once, it became important to run AI every day without draining the battery too much.

Professor Owl

Exactly. There were also more situations where we wanted to process things on the device without going online, so a circuit with AI-specific efficiency became necessary.

PowerOn smartphones and laptops, running AI can't drain the battery a lot every time.
HeatRunning a heavy load for a long time creates heat, and the device may throttle its performance.
LatencyAuthentication and camera correction need to respond right away as you use the device.
Network dependenceSending data to the cloud every time is affected by connection quality and transfer time.
Processing in the cloud
Device → Network → Cloud → Network → Device

Suited to large models and heavy processing, but it goes through the network.

Processing on the device
Device → NPU → Result

For supported tasks, it can run inside the device without waiting for the network.

Don't get this wrong: On-device AI is not always fast, secure, or fully offline. It depends on the AI model, the app, the device, and how work is split with the cloud.

One-line summary so far: The need to run always-on AI on the device with low latency and low power made NPUs necessary.

How does an NPU compute inside the chip?

Naoki

What does an AI-specific circuit actually do inside?

Professor Owl

It runs the "multiply and add" calculations that show up again and again in neural networks, in parallel across many compute units.

Naoki

So it doesn't just add more compute units, it also keeps the data it uses nearby?

Professor Owl

That's the key point. It reuses the same weights and inputs close by and cuts down on trips to external memory.

External DRAMWeights and input data
→
On-chip memoryKeeps the data in use close to the compute units
→
MAC / PE arrayRuns many multiply + add operations in parallel

ResultOn to the next step
Reuse the same weights and inputs many times close by, cutting trips to distant memory

MAC stands for Multiply-Accumulate, an operation that "multiplies and then adds the result." PE stands for Processing Element, a small processing unit that handles these calculations.

NPUs may also use small number formats such as INT8. Making each number smaller, within the range that keeps the needed accuracy, reduces the load on the compute circuits and data transfer.

Structure differs by product: The number of MACs and PEs, the memory hierarchy, how data flows, and the supported number precision vary by vendor and generation. The diagram is a simplified view of the shared idea.

One-line summary so far: An NPU combines many compute units with nearby memory and runs AI calculations while reusing the same data.

Why can NPUs process with less power?

Naoki

"It saves power because it's dedicated" still feels a bit vague to me.

Professor Owl

Then let's split the places where waste is cut into four: instruction control, parallel computing, data movement, and number size.

Naoki

So it cuts not only the power for computing itself but also the power for moving data.

Professor Owl

In fact, in AI, trips to and from distant memory can have a big effect on efficiency.

1. Less general-purpose controlInstead of having all the wide-ranging instructions, complex branching, and reordering a CPU has, it narrows its circuits to the AI tasks it supports.
2. Parallel MACsIt runs the multiply-accumulate operations repeated in matrix math and convolution at the same time across many PEs.
3. Less data movementIt keeps weights and inputs in on-chip memory and reuses them, limiting trips to external DRAM, which cost a lot of power.
4. Low-precision computingIt uses formats like INT8 depending on the use, making the compute circuits smaller and reducing the amount of data moved each time.

NPUs combine these four to reduce the energy needed for each AI inference. However, if the model is not supported by the NPU, frequently goes back to memory, or needs a lot of conversion, it may not be as efficient as expected.

One-line summary so far: NPUs cut waste in computing, control, data movement, and number formats all together.

How do the CPU, GPU, and NPU divide the work?

Naoki

If NPUs are good at AI, does that mean we won't need CPUs and GPUs for AI?

Professor Owl

They won't go away. The NPU is a partner inside the SoC. The CPU controls everything, the GPU handles large parallel computing, and the NPU makes supported inference highly efficient.

Naoki

So instead of picking one all-rounder, you send each task to what it's good at.

Professor Owl

Exactly. Training is still mostly done on GPUs and in data centers, and the NPU in a device mainly handles inference.

ProcessorMain roleHow it is used in AI
CPUDecisions, control, wide range of instructionsRuns the overall flow of apps and tasks with lots of branching
GPUFlexible large-scale parallel computingShines in compute-heavy work such as large-scale training and inference
NPUDedicated to supported AI calculationsMainly makes it easier to keep running inference on the device with low latency and low power

One-line summary so far: The NPU is not a substitute for the CPU/GPU, but a partner inside the SoC that takes on AI inference.

How did the shift toward NPUs happen?

Naoki

Was the NPU a technology that suddenly appeared for smartphones?

Professor Owl

It didn't start with a single invention. It's easier to understand as a flow: AI inference grew in scale, the efficiency of dedicated circuits was shown, and that was tied to concrete device features.

1AI inference grows, and general-purpose processing alone becomes costly in power efficiency

Running neural networks at scale in real services makes the amount of computing and power a major issue. Google began deploying TPUs in its data centers in 2015.

2A 2017 TPU paper concretely shows the efficiency of a dedicated ASIC

Google's paper reported a structure with an 8-bit MAC matrix unit, large on-chip memory, and limited general-purpose functions. The value of specializing for AI inference became visible as data from real operations.

3In the same year, 2017, the A11 Neural Engine is tied to device features

Apple tied the Neural Engine in the A11 Bionic to Face ID, Animoji, and more. Users could see dedicated circuits supporting everyday authentication and real-time processing on the device.

4With the A12 in 2018, the range of on-device AI widens

The A12's Neural Engine became available through Core ML, widening what developers could use it for in supported apps. For certain Core ML tasks, Apple claims up to 9 times faster than the A11, using as little as one-tenth the energy.

How to read this history: This is not a timeline to decide "the first NPU." It shows the cause and effect of dedicated AI circuits proving their efficiency in data centers and then spreading to concrete device features and development environments. Manufacturer-claimed figures depend on the target task and measurement conditions.

One sentence to remember: Growing AI inference called for dedicated circuits, the TPU showed their efficiency, and the A11 and A12 brought them into everyday device features.

What did NPUs improve in everyday life?

Naoki

From the user's side, what changed because of NPUs?

Professor Owl

Face ID is an easy example. It supported the whole chain of processing face information from the camera with a neural network and matching it on the device.

Naoki

So it matters not just that it's fast, but that it can respond without sending data to the cloud every time.

Professor Owl

That's right. Today it has spread to camera correction, noise reduction, speech recognition, translation, on-device generative AI, and more.

Response timeRunning supported tasks on the device makes it easier to return results without waiting for a round trip over the network.
Possibly no network neededSome features can work offline. However, some features also use the cloud.
Keeping data on the deviceDesigns that process input data without sending it out are possible. However, how data is actually handled differs by app.
Battery and heatIf the same supported inference can be done with less energy, it helps with longer operation and less heat.
Camera and voiceSupports real-time tasks such as correction, recognition, noise reduction, transcription, and translation.
On-device generative AIMore uses are appearing where supported small models handle summarizing, generating, search assistance, and more on the device.

One-line summary so far: NPUs are the foundation for using AI quickly and continuously as an everyday feature, not just a demo.

Going one step deeper

The rest is for readers who want to check NPU performance figures and software requirements. If you only want the basics, feel free to skip to the summary.

Can NPU performance be compared by numbers alone?

With NPUs, you often see a metric called TOPS, which shows the number of operations per second. But TOPS alone does not decide actual speed or battery life. Number precision, on-chip memory capacity, external memory bandwidth, model shape, power limits, and more all play a part.

When comparing: It is important not to line up TOPS figures given at different precisions or measurement conditions side by side as-is. This article does not rank specific products.

Extending your understanding of NPUs to uses and learning environments

Once you understand NPUs, sort out which tasks you want to use, such as voice, images, or text, and whether they run on the device or use the cloud. For a home practice PC, go back to the system requirements of the software you need and compare. Having an NPU alone does not mean all generative AI will run fast. You can compare, by purpose, courses that teach how to summarize public documents and write text, and options for upgrading the PC itself.

Checklist before comparing: the CPU, GPU, and NPU supported by the AI software you will use, the OS, memory, and storage. Separate what you can try with your current setup from what needs upgrading before choosing candidates.

Does having an NPU make all AI faster?

No. The AI model must be converted into a format the NPU supports, and the OS, drivers, compiler, and runtime need to assign the work correctly. Unsupported operations may fall back to the CPU or GPU.

In other words, an NPU is not complete with circuits alone. Only when it is connected to supported models and software does it deliver the efficiency of on-device AI.

One-line summary so far: Look at an NPU not just by circuit performance but as a whole system including models, memory, and compilers.

Summary

3 points to remember first

  1. An NPU is a dedicated accelerator that runs neural network inference on the device with low latency and low power
  2. It cuts waste in computing and data movement with many MACs/PEs, nearby memory, data reuse, and low-precision computing
  3. The CPU handles control, the GPU handles large-scale parallel work, and the NPU makes supported inference highly efficient, all working together with software
