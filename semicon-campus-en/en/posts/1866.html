On October 6, 2026, Keysight announced a feature that connects AI agents to "ADS 2027," its design software for RF (radio frequency) circuits, to automate design work. The intended flow starts from a request in natural language, moves through circuit design, setup, and simulation inside ADS, then analyzes and checks the results. According to Keysight's announcement, the features are available in ADS 2027 and RF Circuit Simulation Professional.

However, it is worth noting what the dates mean. The product release date of ADS 2027 itself was August 4, 2026, and the October 6 announcement was a news release explaining the configuration and uses of the AI features, rather than the first availability date of a new product. So it is not accurate to read it as "AI chip design software was completed for the first time on October 6." The August 4 release record can be confirmed in the ADS 2027 product release information and the product listing.

What was announced?

At the center of this news is a configuration that places an "MCP server" between ADS and AI agents. MCP stands for Model Context Protocol, a common mechanism for connecting AI models with external software. In the official specification, an MCP server provides the AI with prompts (descriptive text), resources (information it can reference), and tools (operations it can run). Its key feature is that the AI does not just return text but can call permitted functions. The official MCP specification describes tools as executable functions controlled by the model.

According to Keysight, the MCP server provides the agent with documented skills and tools for RF design. The agent calls ADS functions to perform design operations, then runs ADS simulations and verifies the output of the generated design. In other words, rather than letting the AI freely operate the EDA software's screens, the idea is to let it use EDA functions through defined entry points. The announcement also shows macro recording, converting graphical designs into code, and Python script generation, in addition to the MCP server.

Technical terms for beginners

What is EDA?

EDA stands for Electronic Design Automation. It refers to the software used to design circuits for semiconductors and wireless devices on a computer and examine their electrical behavior before building prototypes. In RF circuits, you need to check not just the schematic but also the frequency characteristics of signals, electromagnetic effects, changes due to heat, and more.

ADS is EDA software for this kind of RF design. ADS 2027's product information includes analysis areas such as circuits, electromagnetics, electrothermal, high-speed digital, quantum, photonics, and power, plus Python automation and MCP-enabled AI workflows. As the product release information and the product listing show, the new AI features are not a standalone chat function but an extension built into the existing analysis environment.

The difference between AI agents and generative AI

While generative AI mainly answers questions and writes code, an AI agent puts together multiple steps toward a goal, calls external tools, and feeds the results into the next step. For example, if you ask it to "look for circuit candidates that improve performance in a certain frequency band," the agent can set up design conditions, create the circuit, run simulations, and compare the results.

The announcement also shows a feature that records an experienced designer's operations as macros for colleagues and agents to reuse. A macro is a recorded sequence of operations that can be run repeatedly. In addition, converting graphical designs into code that AI can handle easily and generating Python scripts make it easier to automate repeated calculations with changed conditions and the processing of design data. Keysight's news release ties these to reusing and automating RF design work.

Why does this matter in semiconductor design?

RF design involves repeatedly creating schematics and layouts, checking characteristics with circuit simulation and electromagnetic analysis, and recalculating with slightly changed conditions. Having a designer enter the same settings every time takes time, while simple automation alone can struggle to handle the step of looking at results and deciding on the next conditions.

Connecting AI agents to EDA may make it possible to turn a goal given in natural language into a series of steps: design operations, analysis, and checking results. Keysight says that if agents handle repetitive setup and simulation, more design candidates can be evaluated in the same development time. However, this is an expected benefit presented by the company, and the materials we can check include no time savings or circuit performance improvements from independent comparison tests, nor any volume-production track record. The benefits described in the announcement need to be kept separate from independent proof.

What it can do and what is still unknown

What we can confirm from the announcement is a product configuration in which an AI agent calls documented RF tools via MCP and verifies the output with ADS simulations while using macros and Python. On the other hand, no feature was announced that sends AI-generated circuits straight to the fab and guarantees manufacturing quality. Simulation is an important part of design verification, but it does not automatically replace manufacturing variation in real chips, parasitic elements in components, measurement environments, or reliability testing.

Also, the primary sources we checked are not enough to confirm the specific list of tools available through MCP, which external LLMs are supported, the authentication method, permission management, conditions for on-premises operation, or whether design data is sent outside. Because MCP is a mechanism that enables operations, real-world use requires managing who can call which tools, how inputs are validated, and whether design rules are being violated. Checking simulation conditions and approval by experts are also essential for final decisions.

Points to watch going forward

Going forward, we need to confirm which RF tasks will actually be automated and how far designs created by agents can be reproduced. The points we especially want to watch are:

  • Specific specs for supported MCP tools, external LLMs, and authentication and permission management
  • Where design data is stored and the conditions under which it is sent to external services
  • Approval stages that humans should check, and how failed simulations are handled
  • Independent verification of time, number of candidates, and performance compared with conventional design flows
  • Track record of use in prototypes, measurement results, and volume-production designs

This news is not about AI completing a semiconductor automatically. It is news that a product concept has taken shape: linking the EDA operations RF designers use through MCP, macros, Python, and simulation, and handing repetitive work to agents. The keys to judging practical use will be whether AI suggestions can be evaluated efficiently as design candidates, and how quality control from simulation through real measurement and volume production is combined.
