On October 16, 2026, SK hynix laid out, in connection with OCP Global Summit 2026 held in San Jose, USA, from October 12 to 15, a direction for redesigning AI racks to be "memory-centric" with CXL at the core. This is not an announcement of finished, mass-produced racks being deployed. It is an introduction to exhibits and system demos that combine CXL 3.2 memory, rack-scale memory pools, KV cache sharing, computational memory, and more. The event dates can also be confirmed in OCP's official information.SK hynix official announcement OCP official event information

What was announced?

SK hynix says it showed a demo that transfers and reuses KV cache in AI agent processing, using CXL pooled memory that can be accessed from multiple servers and GPUs. KV cache is data that a large language model (LLM) temporarily stores while generating text. It holds the results already computed for the input it has read. As conversations get longer, or the same information is used in multiple processes, the required capacity grows.

For its second-generation CMM-DDR5, the company describes 256GB of capacity, more than twice the bandwidth of the previous generation, and about a 30% improvement in energy efficiency. The official article gives the bandwidth as 80GB/s. However, these are SK hynix's descriptions of its product and demo, and these materials alone cannot be taken as independently tested, industry-wide figures.SK hynix official announcement

In another demo, the company says it showed hybrid memory combining CXL memory and SSDs together with AMD, Penguin, Xcena, and Arcee. According to SK hynix, this setup predicts the needed KV cache from conversation and task history and prefetches it into DRAM. This is also a description of an exhibit and demonstration, not a confirmed announcement of mass production specifications or general availability.SK hynix official announcement

An easy guide to CXL and memory pools

CXL is a standard based on PCI Express for connecting CPUs, GPUs, accelerators, memory devices, and more. In a typical server, memory is fixed in place near each server or GPU. With CXL, on the other hand, it is possible to aim for a setup where memory is separated from compute devices to some extent and treated as an external memory resource.CXL Consortium CXL 3.0 technical white paper

Memory pooling is the idea that multiple servers are allocated the capacity they need from a shared memory resource and return it when they no longer need it. This may reduce imbalances where one server has spare memory while another runs short.

However, "pooling" and "sharing" do not mean the same thing. Pooling is a mechanism for reassigning capacity to the devices that need it. Memory sharing means multiple hosts read and update the same memory region while keeping the data consistent. The CXL 3.0 white paper describes coherent access from multiple hosts and fabric features, which is consistent with the technical background supporting the rack-scale resource sharing SK hynix showed.CXL Consortium CXL 3.0 technical white paper

Why memory-centric design matters in the AI era

AI performance is not determined only by the number of compute units. Where model weights, input data, long conversation histories, and KV cache are stored, and which path is used to read them, also matter. Copying KV cache to each GPU or server increases the burden of capacity and data movement. If it can be stored in shared or pooled memory and reused by other inference processes, the number of copies may be reduced.

However, the actual effect depends on the CXL switch configuration, software, access contention, cache locality, and the conditions of comparison with networking approaches. SK hynix describes a demo comparing against an approach that relies on network communication, but the official article does not give enough detail on specific latency, throughput, power consumption, or measurement conditions. So the statement that "performance improved" should be treated as the company's demo result.SK hynix official announcement

Computational memory such as CMM-Ax is the idea of running some calculations on the memory side, instead of moving data to the CPU or GPU before processing it. For workloads with a lot of data movement, it may reduce the amount moved and save time and power. On the other hand, the supported operations, calculation accuracy, programming model, and compatibility with existing AI frameworks are conditions for practical use. SK hynix says it can lower power and cost burdens, but general savings have not been proven.SK hynix official announcement

Do not confuse standards with product generations

In this news, it is important to distinguish CXL 3.2 from CXL 4.0. The CMM-DDR5 that SK hynix introduced is described as supporting CXL 3.2. Meanwhile, the CXL Consortium announced the release of the CXL 4.0 specification on November 18, 2025, saying it adds link speeds of up to 128GT/s, bundled ports, enhanced memory RAS, and more. Just because CXL 4.0 is a newer standard does not mean this CMM-DDR5 is a CXL 4.0 product.CXL Consortium CXL 4.0 announcement SK hynix official announcement

Limits on the road to mass production, and what to watch next

What can be confirmed this time is that SK hynix presented real system demos and PoC content at a trade show. The mass production start date, price, adopting customers, scope of general availability, and operating costs for a whole rack cannot be confirmed from the official announcement. The figures of 256GB, 80GB/s, and about 30% improvement are also the company's descriptions, not confirmed by independent testing.

Going forward, three points are worth watching: first, how well CXL memory and AI software work together in real operations; second, whether latency and power improvements from KV cache sharing are confirmed by third-party measurements; and third, which operations CMM-Ax supports and how it connects to existing LLM frameworks. Memory-centric AI racks are a promising design direction, but moving from demos to mass-produced systems will require verification of standards, software, reliability, and cost.
