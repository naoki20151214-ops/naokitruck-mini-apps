Learning level Beginner

This article is for readers who already know NAND is memory for storing data and want to learn how data is managed inside an SSD.

An SSD controller is the command center that receives instructions from a PC or smartphone and decides where in the NAND to store data. It spreads out writes and fixes errors during reads, turning NAND into storage that is easy to use.

If you want to review memory basics first, read The Difference Between CPU, Memory, and Storage, then The Difference Between DRAM and NAND. This will make the article easier to follow.

What is an SSD controller?

Naoki

An SSD is a device that stores data in NAND, right? Do we really need a controller?

Professor Owl

NAND is where data is stored, but it does not understand and manage the PC's commands on its own. A command center is needed in between.

Naoki

So NAND is the warehouse, and the controller is the person who manages package addresses and what goes in and out.

Professor Owl

That is a good starting point. In reality, an LSI chip and firmware bridge the host's commands and the physical operation of the NAND.

The short answer: An SSD controller is not NAND itself. It is a logic chip plus control software that manages NAND so it can be used as storage.

Summary so far: The SSD controller is the command center that connects the host and the NAND.

Why NAND alone does not make an SSD

Naoki

Couldn't we just write the file name and storage location directly to the NAND?

Professor Owl

The host sends commands using logical numbers, but NAND writes in pages and erases in blocks. They use different units and rules.

Naoki

So we need to translate the PC's addresses into the actual shelf numbers inside the NAND.

Professor Owl

Exactly. On top of that, cells have a limited number of rewrites, and errors can happen. The controller manages not just locations but how the NAND is used.

Write and erase units are differentNAND writes to pages and erases in blocks, which contain multiple pages.
Writes cannot pile up in one placeIf rewrites are concentrated in one area, those blocks tend to wear out faster.
Prepare for read errorsThe controller detects and corrects bit errors that occur depending on storage density and usage.

Summary so far: NAND's physical rules must be translated into an easy-to-use storage device.

3 jobs to learn first

Naoki

It seems to have lots of functions. What should I learn first?

Professor Owl

Deciding where to store data, spreading out writes, and fixing errors. Start with these 3.

Naoki

So it plays 3 roles: address clerk, lifespan protector, and data protector.

Professor Owl

Nicely organized. In reality there is also parallel processing, encryption, power management, and more, but how these are implemented differs by product.

The SSD controller handles address translation, spreading the rewrite load, and data protection all together.

You now understand the basics of the SSD controller.
Going one step deeper

The rest of this article is for readers who want to learn about FTL, wear leveling, ECC, and garbage collection. If you only want the basics, feel free to skip to the Summary.

FTL: Matching visible addresses to actual locations

Naoki

When I overwrite the same file, does it get written to the same cells?

Professor Owl

Not necessarily the same place. The FTL updates the mapping between logical addresses and physical addresses.

Naoki

So even if the user sees the same address, the actual storage shelf can be swapped.

Professor Owl

Right. FTL stands for Flash Translation Layer. It holds that mapping table and is the core of NAND management.

Technical note: In a typical SSD, the host accesses data using logical block numbers called LBAs, and the controller maps them to physical locations in the NAND. The mapping method and the division of work between host and device differ by product and approach.

Summary so far: The FTL maps the host's addresses to the actual locations in the NAND.

Wear leveling: Reducing uneven rewrites

Naoki

If some data is updated often, won't just that spot wear out?

Professor Owl

That is why the controller spreads out where data is written, so erase counts do not pile up on specific blocks.

Naoki

It's like rotating your shoes instead of wearing out just one pair.

Professor Owl

That is a close analogy. But lifespan also depends on the type of NAND, temperature, amount of writing, and control method.

Summary so far: Wear leveling spreads out the load of erasing and writing.

ECC: Fixing errors in data that is read

Naoki

Can't the stored 0s and 1s just be read back exactly?

Professor Owl

Variation in charge states and wear can cause bit errors during reads. ECC detects and corrects them.

Naoki

So it stores extra information for checking answers, and uses it to find and fix mistakes.

Professor Owl

That understanding is fine. The correction capability and method differ depending on the NAND and controller design.

Summary so far: ECC detects read errors and restores the original data, within the range it can correct.

Garbage collection: Creating blocks that can be erased

Naoki

Can't new data be written right away where a deleted file was?

Professor Owl

NAND erases in blocks. The pages you want to keep must be moved elsewhere before the block can be erased.

Naoki

So you move the packages you need to another shelf, then empty the whole shelf and reuse it.

Professor Owl

Yes. This behind-the-scenes moving and erasing also affects performance and the amount of extra writing.

How it differs from TRIM: TRIM is a way for the host to tell the SSD, "This logical area is no longer needed." Garbage collection has a different role: it actually moves valid data, erases blocks, and creates free space.

Summary so far: Garbage collection moves needed data out of the way so blocks can be reused.

Choosing your own storage setup based on how SSDs work

Once you understand the role of the SSD controller, compare products after sorting out how much data you store, how much you write, and what interface your device uses. Check not only maximum speed but also warranty and endurance ratings, capacity, and temperature conditions. Back up the data you need before replacing a drive, and if swapping parts is difficult, you can also compare against upgrading the whole PC. People with evaluation or inspection experience can extend this knowledge to product quality and equipment jobs.

Notes to check before comparing: M.2 size, SATA/NVMe support, capacity, warranty, endurance, and how to migrate. Separate what you can try with your current setup from what needs upgrading, then choose your candidates.

The controller shapes an SSD's character

PerformanceParallel use of multiple NAND channels, queue handling, caching, and firmware design all have an effect.
Endurance and reliabilityWear leveling, ECC, bad block management, and power-loss protection all play a part.
Optimization for useConsumer, data center, and embedded SSDs prioritize performance, power consumption, and protection features differently.

Not all SSDs have the same functions or configuration. Whether there is a DRAM cache, the ECC method, spare area, power-loss protection, encryption, and more differ by product. You cannot simply conclude "same NAND means same performance."

Summary so far: An SSD is a system that includes not only NAND but also a controller and firmware.
