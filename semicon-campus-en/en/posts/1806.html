What happened?

On September 30, 2026, Shibaura Institute of Technology announced that "Ozaki Scheme II," a computing algorithm developed by Professor Katsuhisa Ozaki and colleagues, had been adopted in NVIDIA's CUDA Toolkit 13.4. The news is that a university research result has been built into CUDA, the standard computing software platform for NVIDIA GPUs, and into the implementation of its matrix computation library, cuBLAS.Shibaura Institute of Technology announcement

NVIDIA's official release notes also explain that cuBLAS uses Ozaki-II for "emulated FP64 matrix multiplication." When it offers a performance advantage, Ozaki-II is chosen instead of the earlier Ozaki-I, and GPUs from the NVIDIA Ampere generation onward are supported. What can be confirmed here is that the algorithm has been implemented as an option in CUDA/cuBLAS. It does not mean Ozaki-II is always used on every GPU and in every calculation.NVIDIA CUDA Toolkit release notes

How can AI GPUs do high-precision computing?

GPUs have dedicated compute units for processing large numbers of matrices in AI training and inference. AI often uses low-precision number formats such as INT8. INT8 is an 8-bit integer. The range and fineness of numbers it can represent are limited, but because large numbers of matching compute units can run at once, it is a format that makes high performance easier to achieve.

On the other hand, weather simulation, seismic analysis, and similar work use a 64-bit floating-point format called FP64 to keep errors small during calculation. FP64, or double precision, is a format that can represent the fractional part of numbers more finely. However, on some GPUs, FP64 matrix units are not as numerous as low-precision units for AI, so calculations can be slower.

Instead of running FP64 matrix multiplication using only FP64 operations, Ozaki Scheme II combines multiple low-precision integer matrix multiplications to reconstruct a result close to high precision. Basically, it properly scales the input data, converts it into integer components that are easy to handle, and finds the remainders for several different moduli. It then computes each integer matrix multiplication and finally converts the result back to the original numbers.Ozaki Scheme II technical paper

What is the Chinese remainder theorem?

At the heart of this method is the Chinese remainder theorem. It is a mathematical idea that a number can be recovered from its remainders when divided by several different numbers.

For example, instead of storing a large number directly, you record it as several pieces of information, such as "the remainder when divided by modulus 3," "the remainder when divided by modulus 5," and "the remainder when divided by modulus 7." If the moduli are pairwise coprime and their product is large enough, the original number can be uniquely recovered from those remainders. Ozaki Scheme II applies this idea to matrix multiplication. It decomposes the input matrices, computes a GEMM for each of several remainder representations, and reconstructs the result.

GEMM is the operation of multiplying matrices together and adding up the results. It appears frequently in both AI neural networks and scientific simulations. The paper shows a configuration that uses INT8 Tensor Cores and combines multiple matrix multiplications to aim for FP64-equivalent accuracy. A key feature of this research is that low-precision compute units can be repurposed for high-precision calculations.Technical paper

Background and what this means

The first version of the Ozaki Scheme II paper was published on April 10, 2025. Later, NVIDIA said in its official technical blog that it released CUDA Toolkit 13.4 on September 9, 2026. The blog introduces Ozaki-II fixed-point emulation in cuBLAS as a feature related to improving the performance of double-precision matrix calculations.NVIDIA official technical blog

NVIDIA's archive also lists CUDA Toolkit 13.4.1 and 13.4.2 as September 2026 releases. Since 13.4.0 is marked separately as a Developer Preview, users need to check the sub-version they install and the supported GPUs.CUDA Toolkit Archive

The significance this time is that a way to use the low-precision matrix units, which have been strengthened as AI spreads, for scientific and technical computing has moved from individual research into a GPU computing library. Users may be able to try it through the emulated FP64 feature provided by CUDA/cuBLAS, without writing the whole algorithm themselves.

Expected uses, and what is still unknown

Shibaura Institute of Technology lists applications in scientific simulations that involve high-precision matrix calculations, such as weather forecasting, earthquake-resistant design, quantum chemistry, and new materials development. However, these are example uses and future hopes shown by the university. The adoption announcement alone does not prove real-world results or shorter computing times in each field.Shibaura Institute of Technology announcement

Technically, the effect also depends on conditions. The number of remainder calculations needed, matrix size, the range of input values, how skewed the numbers are, GPU generation, memory usage, and more affect speed and accuracy. The measurements in the paper are research experiments based on specific GPUs, matrix sizes, and implementation conditions. Those numbers cannot be applied directly to all NVIDIA GPUs or real applications.

Also, "FP64-equivalent" does not mean the result will be exactly the same as native FP64 for any input. Whether the scaling and reconstruction range are appropriate, and whether rounding errors stay within acceptable limits, need to be verified for each use. What can be confirmed from public materials is the implementation in CUDA/cuBLAS and the experimental results in the paper. It is not that the same performance and accuracy will be achieved for every matrix size and scientific application.NVIDIA release notes Technical paper

What to watch next

Going forward, the key points to check are under what conditions cuBLAS chooses Ozaki-II in actual CUDA 13.4 releases, and how speed changes by GPU generation and matrix size. For scientific computing users, it will be important to compare native FP64, Ozaki-I, and Ozaki-II on the same problem and measure accuracy, processing time, and memory usage.

It is also worth watching whether verification and reproducibility of results are confirmed in real applications such as weather, earthquake engineering, and quantum chemistry. This news is a big step in that a research algorithm has been built into GPU software used worldwide. But its practical value will be judged by independent benchmarks and adoption cases that build up from here.
